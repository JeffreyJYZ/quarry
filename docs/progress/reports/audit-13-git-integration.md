# Audit 13 — git integration

## Findings

- **P1 — Every git subprocess can hang forever on a huge repo.** `relative_path.rs:100-106` (`run`) and every direct `Command::new(&program)...output()` call (`git_stage.rs:43-48`, `parse_git_blame.rs:116-120`, `parse_git_blame.rs:133-137`, `build_hunk_patch.rs:119-124`, `discard_restore_argv.rs:51-54`, `discard_restore_argv.rs:65-68`, `commit.rs:24-27`, `commit.rs:37-40`, `commit.rs:52-55`, `commit.rs:111-114`, `file_diff.rs:15-24`, `file_diff.rs:66-77`) use blocking `.output()` with no timeout or cancellation. A repo with millions of untracked files (or a slow mount) freezes the `spawn_blocking` thread and the panel with no feedback. Fix: run git behind a deadline (kill the child after, e.g., 30 s) and return `operation_error`; keep `status` on `--untracked-files=all` but make it cancellable.
- **P2 — Hunk staging collides on a shared temp path.** `build_hunk_patch.rs:113-124` writes the patch to `std::env::temp_dir().join(format!("quarry-hunk-{}.patch", id))`, a name derived only from the hunk id, then calls `git apply --cached <tmp>`. Two windows staging the same hunk id race on one file, and a crashed run leaves a stale patch that the next run reuses. Fix: create a uniquely named temp file (pid + counter or `tempfile`), pass its path, and remove it on every exit.
- **P2 — `untracked_diff` emits unquoted paths.** `relative_path.rs:78-97` builds `diff --git a/{path} b/{path}` and `+++ b/{path}` with the raw path. For a file whose name contains a space or other special byte, the resulting patch is not parseable by `git apply`, so staging a hunk on an untracked file with such a name fails or applies to the wrong path. Fix: apply git's C-style quoting (or let `git diff` produce the header).
- **P2 — Read-only failures are reported as "empty".** `file_diff.rs:26-35` returns an empty `GitStatus` whenever stderr contains "not a git repository"; `commit.rs:94-100` (`branches`) and `validate_branch_name.rs:74-80` (`log`) do the same, and `relative_path.rs:59-68` (`is_untracked`) returns `false` on any error. A bad root, a permission error, or a corrupt `.git` therefore looks like "no changes / no branches / no commits" instead of an error. Fix: map only the literal not-a-repository case to empty; propagate every other failure (and surface it in `useGitState`/`useChanges`).
- **P3 — `validate_path` keeps absolute paths and hands them to git.** `git_stage.rs:60-75` validates an absolute path but returns it unchanged, so `git add -- /abs/...` relies on git's pathspec handling of absolute paths (works on the tested git, but is not specified and differs across versions). Fix: convert validated paths to root-relative before building argv, matching `relative_path()` used by `file_diff`/`blame`.
- **P3 — Trimming corrupts filenames with meaningful edge whitespace.** `parse_entry.rs:34` (`? ` branch uses `rest.trim()`) and `parse_entry.rs:120` (`rename_path` uses `path.trim()`) strip leading/trailing spaces from a path. Git only omits such a trim when the name is quoted, so an unquoted name cannot contain it — but a quoted name that legitimately starts/ends with a space loses those bytes after `unquote_path`. Fix: trim only the single field separator, then unquote; do not trim inside the quoted payload.
- **P3 — Hunk patch temp file is not unique and not cleaned on panic.** Covered by the P2 temp-path finding above.

## Checked, no issue

- No git invocation runs during a build. `src-tauri/build.rs` is only `tauri_build::build()`; `tauri.conf.json` `beforeBuildCommand` is `bun run build` (`bun run typecheck && vite build`); `package.json` has no git step. Nothing touches the index at build time.
- Stage/unstage/discard all use `--` separators (`git_stage.rs:45`, `discard_restore_argv.rs:13-21`) and `validate_paths` rejects `..` components and empty lists, so a crafted path cannot escape the root or become a flag.
- `status` parsing preserves spaces in the last field via `splitn(8, ' ')` / `splitn(9, ' ')` / `splitn(10, ' ')` (`parse_entry.rs:46`, `:56`, `:66`), and `unquote_path` reverses git's C-style quoting, including octal escapes. Rename lines use the tab separator (`rename_path`, `parse_entry.rs:115-121`).
- The frontend does not swallow git errors: `useGitState.ts:42-46` and `useChanges.ts:62-67`/`:87-91` call `onNotice`/`setError` on failure; `SourceControl.tsx` renders an error rail when `status === null && changes.error !== null`.
- No second writer on the index from the app: mutations go through `git add`, `git restore --staged`, `git restore --worktree`, `git clean -f`, `git apply --cached` only, each scoped to validated paths.
