## 2. Remaining gaps

1. **Rust expression evaluation — works; the old verdict was a request-shape bug.** `dap_evaluate` answers every expression once the request carries the stop's top `frameId`; without it lldb-dap refuses each one on a stopped process, which read as "Rust is unsupported". Measured for `u32` arithmetic, a field read and a `String` in both Rust and C: `scripts/dap-eval-contexts.ts`, table in `docs/spikes/evaluate.md`. The Default context is `watch`, whose answer is the bare value with the type in its own field. The memory and disassembly `Go to` fields resolve expressions through the same command (`src/lib/debug/memory/resolve.ts`), so `&x`, `p` and `head->next` work as addresses.
2. **Run configuration beyond the run form.** Debug presets are editable from the debug panel (`Edit presets` in `src/ui/debug/DebugPanel.tsx` over `src/lib/debug/presets.ts`): add, duplicate, remove, reorder, and edit name, program, args, cwd, stop-on-entry, `build` and `initCommands`. `build` is a single-line field holding the preset's build command, and `initCommands` is a textarea holding one command per non-empty line, with an inline hint naming the `command script import <sysroot>/lib/rustlib/etc/lldb_lookup.py` line Rust pretty printing needs (`RUST_PRETTY_HINT` in `src/ui/debug/DebugPanel.tsx`, backed by `splitInitCommands` and `joinInitCommands` in `src/lib/debug/presets.ts`). Saves go through `run_config::write_launch_config`, which rejects empty and duplicate names, with client-side validation before the write. Args are typed as one string and parsed with the run form's own `splitArgs` (`src/lib/run/splitArgs.ts`, imported by `src/lib/debug/presets.ts`), rendered back for display by `joinArgs`, so `a "b c" d` keeps `b c` as one argument in both places. An element holding a literal `"` or `\` round trips: `joinArgs` escapes both inside the quotes it emits and `splitArgs` honours exactly those two escapes inside quotes, so `say "hi"` and `C:\temp` survive an edit. `build` is a shell line run before the launch (`src/lib/debug/buildCommand.ts`), through the user's login shell so a Homebrew PATH is present; a failure stops the launch and reports the tail of its output. Independently of it, a launch that fails for a missing binary offers one build, which runs `buildProject(root, buildProfile)` (`src/lib/debug/useBuildBinary.ts`) using the toolbar's Debug/Release choice (`BUILD_PROFILE_CHOICES` in `src/lib/consts/build.ts`, carried into the session by `src/lib/debug/useLaunch.ts` and turned into a program by `resolveDebugArtifact` in `src/lib/debug/profile.ts`). The preset's own `build` command now runs before its launch (`runPresetBuild` in `src/lib/debug/buildCommand.ts`), so nothing here remains open.

## 3. Definition of done for the daily loop at parity

A future agent ticks each item without judgement. All must hold on a Cargo project on this machine.

- [ ] Open a folder containing `Cargo.toml`; the project kind reports `cargo` and toolchains list `cargo`, `rust-analyzer`, `rustfmt`, `lldb-dap`.
- [ ] Open a Rust source file; hover, go-to-definition, references and completion return results from `rust-analyzer`; verified by `bun run scripts/lsp-ux-smoke.ts`.
- [ ] `lsp_symbols` returns a document outline; the outline panel renders it.
- [ ] Save a file with a formatting error fixed by `rustfmt`; format-on-save applies it; a missing formatter surfaces a warning, not a silent no-op.
- [ ] `build_project` runs `cargo build --message-format=json`; its diagnostics appear in the Problems dock.
- [ ] A failing test shows as failed in the Tests dock via `list_tests` and `run_test`.
- [ ] A launch from `.quarry/launch.json` starts under `lldb-dap`; a line breakpoint verifies; variables, scopes and frames populate; memory and disassembly panes render.
- [ ] A hardware watchpoint set via `dap_set_data_breakpoints` fires and stops the process.
- [ ] Rust `Vec` and `String` render pretty-printed, proving `initCommands` loaded `lldb_lookup.py`.
- [ ] `search_project` returns grouped results with a visible truncation cap when exceeded.
- [ ] Git status and per-file diff render in the Source Control view.
- [ ] `bun run check` passes.
- [ ] `cd src-tauri && cargo test` passes.

## 5. Risks that could silently regress

- **rust-analyzer formatter component.** `format::formatter_for` depends on `rustfmt` on `PATH`; a GUI launch carries launchd's `PATH`, so rustfmt may be missing even when it exists in a terminal. Symptom: format on save silently no-ops or warns. Mitigation: probe via `xcrun` fallback and surface the warning.
- **cmake absence.** `cmake` and `ninja` are not installed on this machine. Any C/C++ build path that assumes them fails at runtime. Mitigation: detect and report missing toolchains; do not assume presence.
- **evaluate fallback.** `evaluate` falls back to Objective-C++ and errors on Rust syntax. A watch pane built on it would look implemented but return errors. Mitigation: gate the feature behind a measured workaround.
- **Crate-wide `cargo fmt` rewriting `lsp.rs`.** `src-tauri/src/lsp/mod.rs` is not rustfmt-clean; a crate-wide format adds an out-of-unit diff. Mitigation: format only the file being edited, e.g. `rustfmt --edition 2024 src/dap/mod.rs`.
- **Two parsers share the args text.** `joinArgs` in `src/lib/debug/presets.ts` quotes any element holding whitespace, a `"` or a `\`, and escapes those two inside the quotes; `splitArgs` in `src/lib/run/splitArgs.ts` honours exactly those escapes inside quotes and keeps a backslash outside quotes literal, so a hand-written `C:\temp` and the language-server args the run form also splits stay unchanged. Symptom to watch for: extending escaping to unquoted text would silently rewrite such paths on the next split. `src/lib/debug/presets.test.ts` asserts the round trip for a quote, a backslash and a mixed element, and `src/lib/run/splitArgs.test.ts` pins the escape rules.
