# Debugging

quarry speaks raw DAP to `lldb-dap`, the adapter Xcode ships. One client drives Rust and C/C++,
because both are LLDB targets underneath.

## Starting a session

Debugging launches the binary the build just produced, with the arguments and working directory from
the selected run configuration. The launch is made against the real path of the project directory;
`/var/…` and `/private/var/…` are different strings to lldb, and a mismatch leaves every breakpoint
unverified.

## Breakpoints

- **Line breakpoints** — click the gutter. Set them before a session starts; they are applied when
  the adapter launches.
- **Conditional and log breakpoints** — a condition is evaluated by lldb, a log message prints without
  stopping.
- **Data breakpoints (watchpoints)** — watch a variable's address and stop when it is written. LLDB
  reports the store's line, which is often the line after the assignment you had in mind.

<Callout tone="note" title="Expression evaluation needs a frame">
	`evaluate` works for Rust and C through this adapter as long as the request carries the stopped
	frame's id — without one LLDB refuses every expression with "can't evaluate expressions when the
	process is running", and reading that message as "Rust is broken" was wrong. The dock always
	sends the frame it is showing, so `n`, `n + 1`, a Rust `String` and `v[0]` evaluate in every
	context: `watch`, `variables`, `clipboard` and the omitted case; `hover` answers a bare variable
	but refuses operators. It is not full Rust: lldb falls back to Objective-C++ for method calls
	(`v.len()`) and `as` casts and reports its "not supported" message. Not measured: closures,
	`&mut` borrows, and side effects such as `x += 1`.
</Callout>

## Frames, scopes and stepping

The debug dock lists threads and their frames; selecting a frame shows its scopes and variables in a
tree, with lazy expansion for deep structures. Stepping is <Kbd>F7</Kbd> into, <Kbd>F8</Kbd> over and

<Kbd>Shift</Kbd>+<Kbd>F8</Kbd> out; <Kbd>F9</Kbd> resumes and <Kbd>Cmd</Kbd>+<Kbd>F10</Kbd> runs to
the caret.

<Callout tone="tip" title="Rust values print properly">
	The debugger imports LLDB's Rust formatter script at session start, so `Vec`, `String` and
	friends arrive as values rather than as raw structs. Without it they silently print as
	internals.
</Callout>

## Memory

The memory view reads the target by address, paged, and renders a hex band with an ASCII column.
Unmapped regions are drawn as such rather than as zeroes. It is available while the target is stopped,
and it works regardless of whether the adapter advertises memory references.

## Disassembly

The disassembly pane follows the selected frame and shows instructions around its instruction
pointer. It opens beside the editor as a split, so source and instructions stay on screen together.
