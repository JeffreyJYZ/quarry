# quarry

Rust and C/C++ IDE. Tauri 2 + React 19 shell; clangd, rust-analyzer and lldb-dap do the real work.

- **Scope: Rust + C/C++ only**, CLion parity on the daily loop. Never a general editor.
- **CLion is the reference for both UI and features** — reverse-engineer it with the `rea` MCP tools when the target behaviour is unclear, instead of guessing; screenshots live in the gitignored `docs/reference/`.
- **Plan is `docs/plans/001-clion-parity.md`** — parity matrix, slices, estimates, non-goals; read before feature work.
- **Non-goals stay non-goals**: profiler, remote, embedded, DB, Docker, AI, plugin API, other languages.
- **Toolchains are detected, never bundled** — probe `PATH` then `xcrun --find`; GUI launch carries launchd's PATH.
- **A PATH-only probe misses Homebrew and cargo binaries** — a Dock-launched app sees `/usr/bin:/bin:/usr/sbin:/sbin`; `src-tauri/src/format/tool_search.rs` therefore searches `PATH` first, then `/opt/homebrew/bin`, `/usr/local/bin` and `$HOME/.cargo/bin`, and `taplo 0.10.0` at `/opt/homebrew/bin/taplo` is only reachable that way.
- **Machine paths**: rustup shims `/opt/homebrew/opt/rustup/bin`; `lldb-dap` and `clang-format` only via `xcrun`; `cmake` and `ninja` exist at `/opt/homebrew/bin` (Homebrew), which a GUI launch does not see on `PATH`.
- **No `cargo run` as a debug launch** — build first, pass `lldb-dap` the binary from cargo JSON.
- **Rust module is `build_task.rs`**, never `build.rs` (Cargo's build script).
- **`src/` only**, `@/*` maps to `./src/*`; no root-level `lib/`.
- **Logic is `src/lib`, rendering is `src/ui`** — the feature directory name is kept on both sides (`lib/editor/theme.ts`, `ui/editor/Editor.tsx`); `@/` for cross-tree imports, relative only inside one directory; consts in `src/lib/consts`.
- **No file over 200 lines** — `scripts/check-file-size.ts` runs as the gate's first step and fails on a new offender or on a stale entry in `docs/refactor/oversized.txt`, which may only shrink.
- **Split Rust by module directories** (`foo.rs` → `foo/mod.rs` + `mod bar;` + `pub use`), so `lib.rs` needs no edit; **never `include!("partN.rs")`**, which keeps one scope and is not a module split at all (measured 2026-10-23: 195 compile errors).
- **Stylesheets split with `bun scripts/split-css.ts <file>`** — section files under `<name>/` plus an `@import` index, so cascade order survives.
- **Gates: `bun check` for types, `bun fmt --check` for formatting, `biome lint` for lint, `bun test` for frontend units, `bun run gate` before a commit** — hard tabs 4 wide, print width 100; warnings fail, so leave zero.
- **C/C++ formatting always expands every brace pair** — `clang-format` gets the nearest `.clang-format` plus `AllowShort*: Never|None|false`, so a one-line body never survives a format.
- **Config files are languages of their own** — `src/lib/editor/languages.ts` maps TOML/JSON/YAML by extension and the names with no revealing one (`Cargo.lock`, `Cargo.toml.orig`, `Gopkg.lock`, `Pipfile`, `poetry.lock`, `uv.lock`, `.cargo/config`), and its single `languageNameForPath` table also feeds the status-bar label so the two cannot drift; CLion ships the same split as bundled `toml`/`json`/`yaml` plugins.
- **Format dispatch is per language, never silent** — JSON is formatted in the frontend keeping the file's indent and trailing newline and leaves invalid text untouched, TOML needs a detected `taplo`/`taplo-cli` or says `no formatter for .toml: install taplo-cli`, YAML names the gap, and Rust/C++ keep the server and clang-format paths.
- **`bun fmt` is the formatter, configured in `bunfig.toml` `[fmt]` (`useTabs`, `tabWidth = 4`, `printWidth = 100`)** — Biome no longer formats; it lints only, so `biome check` would flag tab/width drift the formatter owns.
- **`bun fmt` also formats Markdown, this file included** — it rewrites `*emphasis*` to `_emphasis_`, so an AGENTS.md edit that skips `bun fmt` fails CI on that commit and on every later one until fixed; run it after editing this file.
- **No `typescript` dependency**: `bun check` is the type checker and `vite build` transpiles; verified by removing the package and passing both (2026-10-22).
- **`bun` only** — never npm; `bun run build` keeps `run` (built-in subcommand).
- **Full-document LSP sync only**; revisit only on a measured stall.
- **One DAP session per project root, but one LSP session per server kind** — rust-analyzer starts only when the root has a `Cargo.toml`, clangd only for a `compile_commands.json`, `CMakeLists.txt` or a C/C++ source, and both run together when both are present; `rootSignals.ts` probes bounded (depth 4, 64 dirs, skipping `target`/`node_modules`/`.git`/`build`/`out`).
- **Every language-server session is keyed `{kind}::{root}`** — the `root` parameter of every `lsp_*` command carries that id, so a request built from a bare project root answers "unknown session" and is swallowed by a `try/catch`, which reads as a dead feature.
- **A feature guard means a _running_ session serves the file** — `servedByRunningServer(path, running)` and `sessionForPath(...)` in `src/lib/lsp/served.ts`; an extension-only check sends a `.c` file to a rust-only project's clangd session and reports an error for it.
- **Distant LSP features read the session from `src/lib/lsp/context.ts`** — the shell publishes root plus running set via `setLspContext`, and `sessionForContext(path)` answers without drilling props through Outline, Goto, breadcrumb, problem actions; the `lsp_*` wrappers throw `expects a session id, got a path` in dev so a missed call site is loud.
- **A server only receives files it serves** — `src/lib/lsp/served.ts` holds one extension table per server (rust-analyzer `.rs`; clangd `.c .h .cc .cpp .cxx .hh .hpp`), and an unserved path is never opened, changed or closed; without that gate rust-analyzer was handed `Cargo.toml`, `Cargo.lock` and `.gitignore`, and the status chip claimed coverage it did not have.
- **PATH-mutating Rust tests share one lock in `src-tauri/src/test_support.rs`** — the helper used to be copied per test module, so each copy held its own `OnceLock` and two modules mutated the process-wide `PATH` at once; a resolve test failed only when a new PATH-reading test changed the schedule.
- **Never publish a crate named `quarry`** — use `quarry-app`, `quarry-lsp`, `quarry-dap`; frontend `@jyz/quarry-*`.
- **MIT.** Zed is GPL-3.0: read its debugger code for patterns, copy nothing.
- **`.gitignore` carries `.DS_Store`** at the top level.
- **`lldb-dap` is Xcode's LLVM 21.0.0**; `readMemory`, `disassemble` and data breakpoints work — measured in `docs/spikes/dap.md`.
- **Terminal rendering and keystrokes belong to xterm, not React** — `useXterm.ts` owns one emulator per PTY; a prompt that repaints itself with carriage returns needs a VT grid, which a line parser cannot be taught. `focusTarget.ts` decides whether a click may take focus.
- **Raw PTY bytes reach the emulator through `subscribeRaw`** in `useTerminalSessions.ts`, which also replays the handshake buffer — a blank panel beside a live pid means a missing subscription, not a PTY fault.
- **Rust pretty printing needs `initCommands: ["command script import <sysroot>/lib/rustlib/etc/lldb_lookup.py"]`** — without it `Vec`/`String` arrive as raw structs, silently.
- **Never gate memory or disassembly on `supportsMemoryReferences`** — it is false while frames carry `instructionPointerReference` and both requests work.
- **`evaluate` is broken for Rust** (falls back to Objective-C++, errors) — no watch-expression pane until a workaround is measured.
- **Data breakpoint `dataId` is `<hex>/<size>` with no `0x`**, `hitBreakpointIds` is null, and the stop reports the line after the store.
- **`realpath` the project directory before `launch`** — `/var/…` versus `/private/var/…` leaves every breakpoint unverified.
- **`cargo fmt` in `src-tauri` rewrites `lsp.rs`** — that file is not rustfmt-clean, so a crate-wide format adds an out-of-unit diff. Format the one file instead: `rustfmt --edition 2024 src/dap.rs`.
- **A dispatched unit's report is a claim, not evidence**: check the call site exists, not just the helper — one shipped an unused `resolveDebugArtifact` and an unwired panel, another left its `lib.rs` registration out, which fails only at runtime.
- **An empty handler is the new unwired panel** — a parity batch shipped four commands with real labels, accelerators and `run: () => {}` plus a keymap file nothing imported; audit command → handler → API → visible result, and `rg 'run: \(\) => \{\}'` in `commandList.ts` must return nothing.
- **Updater signing key: private `~/.tauri/quarry-updater.key` (no password), public key in `src-tauri/tauri.conf.json` `plugins.updater.pubkey`** — never print or commit the private one, never rotate it once a release ships, or every installed app orphans.
- **A local `bun run tauri build` needs `TAURI_SIGNING_PRIVATE_KEY` set** (the key path or content) because `bundle.createUpdaterArtifacts` is on; without it the bundler refuses to produce updater artefacts.
- **Alphas publish from this Mac with `bun run release:local`** — signed macOS bundle, `latest.json`, release, then a check that the public manifest serves it.
- **CI builds all three platforms only for `quarry-beta*` and `v*` tags**, or a manual dispatch; `scripts/bump-version.ts` keeps the three version files in step.
- **The workflow builds Windows, so Rust must compile there**: gate every `std::os::unix`, `PermissionsExt` and `from_mode` behind `#[cfg(unix)]`; a macOS-only build hides it until CI.
- **Linux bundles AppImage and Windows nsis only** — the deb and msi bundlers reject the hyphen in `X.Y.Z-alpha.N` (`invalid version`), AppImage and nsis accept it.
- **Main agent may push alpha tags and publish test releases here; subagents never push, tag or release.** Tag `quarry-alphaN` pairs with version `X.Y.Z-alpha.N` (`bun scripts/bump-version.ts alpha`), and a stable tag is `v<version>`.
- **Standing permission (user, 2026-10-26): release an alpha whenever there is something to ship — no ask, no "want me to cut a release?"**; bump, push, `bun run release:local`, report the URL.
- **`release:local` refuses a commit whose CI run has failed or been cancelled, and runs `bun run gate` itself before building** — it does not wait on a queued or running run (CI repeats the same nine steps), and `--skip-ci` is the loud escape hatch for both checks.
- **The updater needs `updater:allow-download` and `updater:allow-install` separately** in `src-tauri/capabilities/default.json`; `allow-download-and-install` covers only that one command, so `download()` then `install()` dies `Command plugin:updater|download not allowed by ACL` at runtime, never at gate.
- **`src/lib/updates/capabilities.test.ts` guards that pairing** — it reads the capability file and the store, so a renamed updater call fails the suite instead of failing silently in the app.
- **The updater installs into the bundle it is running from, so a second copy silently freezes** — `2026-10-26`: `/Applications/quarry.app` sat at `alpha.7` while alpha.16/17 self-updated the repo bundle; check both `defaults read <app>/Contents/Info.plist CFBundleShortVersionString` values when a version looks wrong.
- **Never swap `/Applications/quarry.app` by hand** — a self-update is the only end-to-end proof the ACL and signature work; replacing the bundle skips the one path that broke (user, 2026-10-26).
- **Verification ladder: `bun run gate` and `bun run build`; Rust adds `cargo test`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`**; LSP work adds `scripts/lsp-*.ts`, debugger work `scripts/dap-*.ts`. The DAP evaluate probe is expected to fail.
